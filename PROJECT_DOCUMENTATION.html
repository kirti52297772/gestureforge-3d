1. Executive Summary & Problem Statement

1.1 Clinical Background

Traditional anatomical education relies heavily on 2D textbooks, static plastic cadaver models, or expensive specialized virtual reality (VR) headsets that induce ocular fatigue and lack tactile integration. In sterile surgical theaters and pathology laboratories, surgeons cannot touch physical keyboards, mice, or touchscreens due to strict microbial aseptic field requirements.

1.2 The Proposed Solution

GestureForge Med 3D bridges this technological gap by providing an end-to-end, zero-latency, browser-based clinical workstation. Using a standard monocular webcam, the system tracks 21 spatial hand landmarks at 60 FPS using MediaPipe Tasks Vision WebAssembly (WASM). It enables touchless manipulation of high-fidelity 3D human organs (Heart, Brain, Lungs, Kidney, Eye), allowing users to orbit, zoom, dissect, and query anatomical substructures without physical contact.

Key Contributions:
  • Touchless Sterile Control: Intuitive gesture heuristics (Pinch selection, Open Palm freeze, Closed Fist orbit, Two-finger zoom, Thumbs-up dissection).
  • Surgical Dissection Mechanics: Interpolates authentic segmented NIH CT scans along surgical vectors to reveal internal ventricles, papillary muscles, and valve planes.
  • Physiological Telemetry: Real-time synchronized Lead II ECG oscilloscope coupled with Web Audio API stethoscope acoustic simulation (S1/S2 heart sounds).
  • Evidence-Based Learning: Dynamic REST API integration with Wikipedia, NCBI PubMed, MedlinePlus, and interactive clinical case quizzes.

3.1 Computer Vision & Hand Landmark Tracking

Located in src/gestures/handTracker.js. The function createHandTracker() initializes Google MediaPipe's vision task model via FilesetResolver.forVisionTasks(). It fetches the lightweight 16-bit floating point model asset (hand_landmarker.task) configured with GPU delegation. 

const vision = await FilesetResolver.forVisionTasks(
  'https://cdn.jsdelivr.net/npm/@mediapipe/tasks-vision@0.10.14/wasm'
);
handLandmarker = await HandLandmarker.createFromOptions(vision, {
  baseOptions: {
    modelAssetPath: '.../hand_landmarker.task',
    delegate: 'GPU'
  },
  runningMode: 'VIDEO',
  numHands: 1
});

During each animation frame, detectForVideo(video, performance.now()) extracts 21 3D landmarks $(x, y, z)$. The 2D skeleton is drawn onto an HTML5 overlay canvas with cyan connecting vectors.

3.2 Algorithmic Gesture Recognition Engine

Located in src/gestures/gestureRecognition.js. Rather than relying on black-box neural gesture classifiers that consume excessive CPU, this module applies deterministic, rotation-invariant geometric heuristics:

  • Pinch Select: Measures Euclidean distance between thumb tip (Landmark 4) and index fingertip (Landmark 8). If $d < 0.055$, triggers surgical selection.
  • Open Palm (Pause Rotation): Evaluates if all four fingers (Index, Middle, Ring, Pinky) are extended relative to their proximal joints.
  • Closed Fist (Orbit Rotate): Evaluates if all fingers are curled toward the palm.
  • Two-Finger Peace (Zoom): Evaluates if Index and Middle fingers are extended while Ring and Pinky are curled.
  • Thumbs-Up (Dissect): Evaluates if the thumb tip is elevated above the wrist while all other digits are curled.

4. Mathematical & Algorithmic Formulations

4.1 Euclidean Pinch Metric

The distance between the thumb tip $(x_4, y_4)$ and index tip $(x_8, y_8)$ is calculated as:

d_{\text{pinch}} = \sqrt{(x_4 - x_8)^2 + (y_4 - y_8)^2}

Selection activates when $d_{\text{pinch}} < \tau$ where $\tau = 0.055$. A temporal debounce constraint ($t_{\text{current}} - t_{\text{last}} \ge 450\text{ ms}$) prevents inadvertent multi-triggering.

4.2 Viewport Mirroring & Coordinate Transformation

Because the user views a mirrored webcam feed, coordinates must undergo horizontal reflection and normalization to Three.js Normalized Device Coordinates (NDC) in the range $[-1, 1]$:

x_{\text{NDC}} = (1 - x_{\text{landmark}}) \cdot 2 - 1 \\ y_{\text{NDC}} = 1 - 2 \cdot y_{\text{landmark}}

4.3 GPU Raycasting Unprojection

To determine which 3D anatomical structure lies under the user's pinch point, the 2D point is unprojected into a 3D ray $\vec{R}(t) = \vec{O} + t \vec{D}$ using the inverse of the camera's view-projection matrix:

\vec{R}_{\text{world}} = \mathbf{M}_{\text{invProjection}} \cdot \mathbf{M}_{\text{invView}} \cdot \begin{bmatrix} x_{\text{NDC}} \\ y_{\text{NDC}} \\ 1 \\ 1 \end{bmatrix}

4.4 Segmented Dissection Vector Interpolation

Each anatomical puzzle section $i$ translates from its assembled resting position $\vec{P}_{0, i}$ to its dissected location along an anatomical displacement vector $\vec{V}_{\text{explode}, i}$:

\vec{P}_i(t) = \vec{P}_{0, i} + t \cdot \vec{V}_{\text{explode}, i} \quad (t \in [0, 1])

For the NIH Heart ALM0006 segmented dataset:

  • Section A (Aorta & Atria): $\vec{V}_A = (0, 72, 25)$ (Displaces superior-anteriorly).
  • Section B (Valvular Plane): $\vec{V}_B = (-80, 0, 20)$ (Displaces laterally to the left).
  • Section C (Ventricular Apex): $\vec{V}_C = (35, -75, -20)$ (Displaces inferior-posteriorly).

4.5 Piecewise Trigonometric Lead II ECG Waveform

The electrocardiogram voltage $V(\phi)$ is mathematically synthesized as a piecewise function over the cardiac cycle phase $\phi \in [0, 1]$:

V(\phi) = \begin{cases} \sin\left(\frac{\phi - 0.12}{0.10} \pi\right) \cdot 0.22, & 0.12 \le \phi < 0.22 \quad \text{(P Wave)} \\ -\sin\left(\frac{\phi - 0.28}{0.02} \pi\right) \cdot 0.18, & 0.28 \le \phi < 0.30 \quad \text{(Q Wave)} \\ 1.35 \cdot \left(1 - 2\left|\frac{\phi - 0.30}{0.05} - 0.5\right|\right), & 0.30 \le \phi < 0.35 \quad \text{(R Peak)} \\ -\sin\left(\frac{\phi - 0.35}{0.03} \pi\right) \cdot 0.35, & 0.35 \le \phi < 0.38 \quad \text{(S Wave)} \\ \sin\left(\frac{\phi - 0.48}{0.14} \pi\right) \cdot 0.38, & 0.48 \le \phi < 0.62 \quad \text{(T Wave)} \\ \mathcal{N}(0, 0.01), & \text{otherwise (Isoelectric Baseline)} \end{cases}

5. Clinical Knowledge Engine & Case Studies

5.1 Real-Time Wikipedia REST API Query Engine

In src/ui/wikipediaModal.js, when an anatomical landmark (e.g., Left Ventricle) is selected, the application issues an asynchronous HTTP GET request: 

https://en.wikipedia.org/api/rest_v1/page/summary/${encodeURIComponent(partTitle)}

The response payload parses the JSON schema to extract:

  • title: Official medical nomenclature.
  • description: Physiological definition.
  • extract: Comprehensive clinical narrative.
  • thumbnail.source: High-resolution anatomical histological image.

It automatically constructs query URLs for NCBI PubMed (https://pubmed.ncbi.nlm.nih.gov/?term=${query}) and MedlinePlus for immediate peer-reviewed journal exploration.

6. Viva Voce Defense: Evaluator Questions & Answers

Q1: Why did you implement this in Three.js and MediaPipe Web rather than Python with OpenCV and PyBullet?
Answer: "Implementing the pipeline natively in WebAssembly (WASM) and WebGL eliminates the latency, network overhead, and complex installation dependencies of Python servers. A browser-native solution runs entirely client-side on the user's GPU at 60 FPS, ensuring zero transmission latency and cross-platform accessibility on any medical workstation without requiring drivers or high-end graphics cards."
Q2: How do you prevent hand jitter and false gesture triggers during surgical inspection?
Answer: "I implemented a three-tier stabilization pipeline: First, a deadzone filter of 0.0025 units discards high-frequency micro-tremors during palm rotation. Second, pinch selection uses an absolute Euclidean threshold of 0.055 combined with a 450 ms timestamp debounce check. Third, closed fist and open palm gestures check mutually exclusive finger flexion states, preventing conflicting command dispatches."
Q3: How does the system map 2D camera coordinates to accurate 3D spatial intersections?
Answer: "The 2D fingertip coordinates are inverted to account for camera mirroring and mapped to Normalized Device Coordinates [-1, 1]. A THREE.Raycaster unprojects this point using the camera's inverse view-projection matrix to create a mathematical 3D ray in world space. The raycaster tests for surface bounding-box intersections with both the organ meshes and the 3D landmark pins, returning the nearest intersected object."
Q4: How did you solve the backface culling and coordinate offset issues on the NIH 3D model?
Answer: "Medical CT segmented models from the NIH 3D Print Exchange often feature non-standard normal orientations. I resolved backface transparency by enabling side: THREE.DoubleSide on all medical PBR materials. Furthermore, because the raw NIH coordinate space was centered at Y = -120 mm, I encapsulated all meshes and pins inside a unified parent transformation matrix that scales by 2.4 / 145 and offsets by -NIH_CENTER * scale, centering the organ at (0, 0, 0) and perfectly aligning the anatomical pins."
Q5: How does the cardiac pulsation deformation synchronize with the ECG waveform?
Answer: "The ECG monitor tracks the physiological phase φ ∈ [0, 1] of the cardiac cycle. At φ = 0.32 (the peak of the R wave indicating ventricular depolarization), an event callback triggers an acute 6% radial systolic contraction on the heart mesh and simultaneously fires the S1 'lub' acoustic oscillator. At φ = 0.58 (the end of the T wave repolarization), the mesh recoils in diastole and triggers the S2 'dub' sound."
